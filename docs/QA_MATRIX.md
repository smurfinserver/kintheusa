## 공통 시나리오

- **홈**: 정확히 16개 카드 표시; 검색/카테고리 필터/초기화/홈 복귀/새로고침 정상 동작; 깨진 경로·콘솔 오류 없음.
- **경로**: localhost / GitHub Pages `/repo/` / 가능하면 커스텀 도메인 루트에서 링크·자산 경로 검증.
- **다운로드**: 내려받은 파일을 실제로 파싱/열고, MIME·내용/형식·픽셀 또는 페이지 수를 확인.
- **모바일**: 375px 이상 소형 화면과 1280px 이상 데스크톱, 가로 스크롤/버튼 겹침 없는지 확인.
- **프라이버시**: 파일 업로드, 주민번호 입력, PDF 생성 시 문서 데이터가 원격 호스트로 전송되지 않는지 개발자 도구의 Network 패널과 자동 테스트로 확인. 외부 요청이 있다면 대상/목적을 문서화.
- **접근성**: 주요 버튼 키보드 접근, 포커스, 상태 메세지, 파일 업로드 레이블, 적절한 대체 설명.
- **오프라인**: 서비스 워커 구현 여부에 맞춰 1회 정상 로드 후 인터넷 차단 상태에서 홈/도구/서식/PDF 합치기 동작을 따로 기록. 미구현 시 BLOCKED/NOT TESTED로 남김.
- **공식 서식 안내**: 실제 신청 가능 여부를 보증하지 않으며 제출 전에 최신 공식 안내 확인. 다운로드 서식은 사용자 제공 판본임을 명시.

## 기본 자동화 추천

- Playwright에서 각 카드 클릭 결과를 확인하고 대표 입력값으로 이미지/PDF/TXT를 다운로드한다.
- 다운로드 경로는 임시 디렉터리를 사용하고 테스트 후 정리한다.
- 원본 PDF는 `original-forms/`의 빈 양식을 사용하거나 별도 합성 테스트 파일을 생성한다.
- 여권/동의서 PDF 생성 테스트는 실제 렌더 결과를 PNG로 변환해 레이아웃/겹침을 확인한다. 글자 추출이 불가능한 이미지 기반 PDF라는 점을 감안한다.
- CI는 배포된 HTTPS URL 테스트와 로컬 단위 테스트를 구분한다. 실제 배포 URL을 확인하지 못하면 배포 테스트는 성공으로 기재하지 않는다.
